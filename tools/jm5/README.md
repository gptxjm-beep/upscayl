# اختبار Windows 11 / RTX 3060 Ti

هذه أدوات قبول مستقلة. لا تُشغّل في البيئة السحابية التي تستخدم Vulkan برمجيًا.
تبقى الصور الأصلية كما هي، وتُحفظ النتائج في مجلدات منفصلة. جهّز 50–100 صورة
تمثل المانهوا الملونة والمانغا والتظليل والصور الصغيرة والصفحات الطويلة. احتفظ
بمجموعة صغيرة أولًا لاختبارات الفشل والاستعادة. لا تختبر انقطاع الكهرباء على
أصولك الوحيدة.

## مقارنة أداء النموذج الواحد بالمرجع jm.4

ثبّت Python مع Pillow، واحصل على محرك jm.4 الأصلي والمحرك المرشح من الحزمتين
المتحقق منهما. استخدم ملفات النماذج نفسها تمامًا:

```powershell
py -m pip install Pillow==11.2.1
py tools/jm5/compare.py --baseline-engine C:\jm4\resources\bin\upscayl-jm.exe `
 --candidate-engine C:\jm5\resources\bin\upscayl-jm.exe `
 --models C:\jm5\resources\models --input C:\Data\Acceptance100 `
 --report C:\Results\jm4-vs-jm5-batch --count 100 --mode batch `
 --model upscayl-standard-4x --scale 2 --tile 200 --gpu 0 --repeats 3 `
 --confirm-gpu-benchmark
```

كرر مع `--mode single` ومجلد تقرير جديد لقياس تشغيل كل صورة بعملية منفصلة على
المحركين. يتطابق Tile/GPU/TTA/الصيغة/الضغط/النموذج والمقياس بين الطرفين. أضف
`--tta` للطرفين معًا عند الحاجة. تعني `--gpu` رقم NCNN؛ راجعه في سجل المحرك، فقد
يختلف عن رقم `nvidia-smi` الذي يُحدد بخيار `--nvidia-index`.

تسجّل الأداة ثلاث دورات على الأقل بترتيب متناوب، زمن العمليات الخام منفصلًا
عن فك المخرجات كاملًا والتحقق من الأبعاد والصيغة، ومتوسط زمن المدخل وعدد
المخرجات السليمة بالدقيقة. تحفظ التشغيل الأول واللاحق كلًا على حدة؛ لا يُفترض
تفريغ كاش النظام أو برنامج التشغيل. تُسجّل بصمات المحركات والنماذج والمدخلات
والمخرجات ورموز الخروج. لا يُفصل زمن التهيئة لعدم وجود علامة جاهزية مشتركة
موثوقة في الإصدارين.

هذه مقارنة للمحرك بنموذج واحد، وليست زمن واجهة التطبيق أو سجل المهام، ولا
تقارن جودة نموذج واحد بجودة نموذجين مختلفين. اختيار ثلاث صور لتحديد أوقات
نشرها ليس بديلًا عن مجموعة الـ100 صورة في اختبار عدم التراجع.

لرصد RAM وVRAM في تجربة مستقلة، افتح PowerShell آخر وشغّل:

```powershell
powershell -NoProfile -File tools/monitor-enhanced-resources.ps1 `
 -DurationSeconds 600 -OutputCsv C:\Results\resources.csv
```

راقب خروج عملية المحرك بعد Paused، وDedicatedUsage وSharedUsage كلًا على حدة.
غياب عدادات WDDM ليس قياسًا لصفر VRAM. لا تستخدم الرصد الإضافي داخل قياس الزمن
الأساسي ثم تقارنه بتشغيل بلا رصد. لا يدّعي التقرير قياس RAM/VRAM إذا لم تُجمع
عدادات موثوقة. قد يحتاج عرض PNG الطويل جدًا إلى برنامج يدعم هذه الأبعاد؛
نجاح مُرمّز PNG لا يضمن دعم كل العارضات.

## النموذجان وPause/Recovery

بعد `npm ci` و`npm run tsc` واستيراد النماذج وفق `tools/models/README.md`:

```powershell
node tools/jm5/run-job.cjs --engine C:\jm5\resources\bin\upscayl-jm.exe `
 --models C:\Models\UpscaylVerified --model 1x-manhwa-null `
 --second-model 4x-illustrationjanai-v1-esrgan --input C:\Data\SmallSet `
 --output C:\Results\TwoStage --scale 2 --tile 100 --gpu 0 `
 --pause-stage CHECKPOINT --confirm-gpu-test
```

يتطلب هذا المثال **Manhwa Null الأصلي بعد اجتياز الاستيراد**؛ اجتاز اختبارات رقمية اصطناعية على Vulkan برمجي بعد استلام الأوزان الأصلية والتحقق من بصمتها؛ تبقى الصفحات الحقيقية وبطاقة NVIDIA للاختبار العملي. لا تستخدم نموذج الاختبار الصغير بدلًا منه.
يمكن تقييم Illustration وManga اللذين اجتازا المقارنة الرقمية، مع مراعاة
المقياس المركب وفحص الموارد قبل التشغيل. ابدأ بصور صغيرة.

أعد الأمر مع `--resume <id>` الذي يظهر في السجل لاستكمال الإعدادات المحفوظة،
واحذف `--pause-stage` كي يكمل. تحقّق من أن أول صورة ذات ناتج وسيط سليم تبدأ
بالمرحلة الثانية فقط. جرّب `STAGE1` و`STAGE2` و`VERIFY` كلًا على مجموعة منفصلة.
تمثل VERIFY مرحلة الحفظ/التحقق؛ يلزم سجل إضافي لإثبات لحظة انقطاع أثناء كتابة
الملف تحديدًا. تمرير ملف إلى `--input` يختبر Single مُدارًا دون جيرانه.

للاستعادة بعد انهيار، استخدم بيانات تجريبية، وأنهِ **عملية المتحكم Node أو
التطبيق** من Task Manager. انتظر توقف محرك الجلسة بعد انتهاء lease، ثم استأنف
من السجل نفسه. لا تحذف سجل المهمة. فشل أو تلف ناتج وسيط يعيد المرحلة الأولى؛
تظل هوية النماذج والصور المكتملة ثابتة. عند استئناف مهمة انتهت بأخطاء يمكن إصلاح ملف فاشل خارجيًا؛ يُثبت هاشه وأبعاده من جديد وتُلغى نتائجه الوسيطة القديمة. تغيير أصل مكتمل يبقى ممنوعًا في الجلسة نفسها. النتائج النهائية المكتملة
تبقى محمية من الكتابة فوقها. لا يحتاج اختبار الاستعادة إلى قطع كهرباء الجهاز.

## ما تشاركه للمراجعة

- `report.json` و`summary.csv` وسجلات `engine.log` لمقارنة الزمن.
- تقارير `acceptance-*.json` وسجلات `.jm5-acceptance/logs` لاختبار النموذجين.
- ملفات `*.model.json` وملفات `*.validation` للنماذج المستوردة، دون الأوزان.
- إصدار تعريف NVIDIA، إعداداتك، وملاحظة عن التطبيقات الأخرى التي تستخدم GPU.
- عند خطأ بصورة طويلة: اسمها وأبعاد الأصل والناتج والسجل، مع عينات مقتصة إن
  كانت مناسبة للمشاركة؛ لا حاجة لإرسال صور خاصة كاملة.

اختبارات الـ1000 المصطنعة الموجودة في CI تثبت البروتوكول والحدود، ولا تثبت
جودة النماذج المدربة أو أداء RTX أو نجاح 1000 صفحة حقيقية.
